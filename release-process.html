The universal constants: T-2 is always certification. Ship day always has 2+ business day runway after it. QA reviews scope at dev complete. Data migrations are locked at T-2. Hotfixes bypass the train but pay the RCA tax.

The Non-Negotiables

1 Cutoffs are hard walls

Miss a cutoff, your ticket rolls. No exceptions. No "just one more." The release ships without it.

2 Master first, always

Every fix lands on master before cherry-pick. No direct commits to release branches. Ever.

3 QA reviews scope at dev complete

QA must confirm they understand what to test, have acceptance criteria, and have estimated effort. No blind handoffs.

4 Data migrations locked at T-2

All migrations documented, staging-tested, rollback-planned, and DBA-approved before certification. No surprise migrations at ship time.

5 Certification = done done done

QA signed off + Nectar green + migrations approved + release notes final. All four. Not three of four.

6 Every release requires an RCA

Every product release (hotfix, point, monthly) requires a Root Cause Analysis. Hotfix RCA due within 48h. Same root cause triggers 2 hotfixes = P0 process issue.

Hard Rules

These are not guidelines. They are laws. Violations trigger escalation.

1 Cutoffs are walls, not suggestions

If your ticket isn't ready by the cutoff, it rolls to the next release. There is no "just this once." The release ships without you.

2 Master first, cherry-pick second

Every line of code lands on master before it touches a release branch. No direct commits to release branches. No "quick fix" shortcuts.

3 Wednesday/Tuesday ship days only

Monthly ships Wednesday, point ships Tuesday. Thu/Fri/Wed are runway to catch fire. Never ship Friday. Never ship Monday.

4 QA scope review at dev complete — no blind handoffs

QA must review every ticket at dev complete, confirm acceptance criteria are testable, and estimate effort. If QA says "I don't know how to test this," dev provides guidance or the ticket is deferred. QA doesn't start testing until scope review is done.

5 Data migrations locked at T-2

Every migration must be documented (script + impact + rollback), tested on staging, and DBA-approved before certification. No surprise migrations. No "we'll run it manually." Nectar flags any schema change without a migration entry.

6 Certification = QA + Nectar + migrations + notes

Four things must be true: (a) QA signed off every ticket, (b) Nectar truth shows zero mismatches, (c) all migrations DBA-approved, (d) release notes final. All four. Not three of four.

7 Post-freeze cherry-picks need two approvals

After cherry-pick freeze, any cherry-pick requires release lead AND CTO approval. Must be P0/S1. PR description includes justification.

8 Bug fix SLAs during QA — 24h or defer

QA finds a bug → dev has 24h to fix on master and open cherry-pick PR. Not fixed in 24h? Ticket deferred or feature reverted.

9 Every product release requires an RCA

Every release (hotfix, point, monthly) requires a Root Cause Analysis documenting what changed and why. Hotfix RCA due within 48h. Same root cause triggers 2+ hotfixes = P0 process failure.

10 Every missed gate gets a RCA

Certification missed or release delayed? RCA within 48h. Output is concrete action items with owners, not "we'll try harder."
